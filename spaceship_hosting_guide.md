# Spaceship.com Hosting & Deployment Guide

This guide provides a step-by-step walkthrough to host your **Vite React Frontend** and **Node.js Express MySQL Backend** on Spaceship.com hosting (which uses the standard cPanel & CloudLinux Node Selector environment).

---

## 🏗️ Deployment Architecture Overview

On a shared hosting server (like Spaceship), we will configure:
1. **Frontend**: The static production bundle generated by Vite (`dist/` folder) will be hosted in your domain's primary root (e.g. `public_html/` or a dedicated subdomain).
2. **Backend**: The Node.js Express server (`server/`) will run as an application managed by cPanel's **Setup Node.js App** (Passenger) and will run locally inside a custom directory.
3. **Database**: A local MySQL database managed via cPanel's **MySQL® Databases**.

---

## 📋 Step-by-Step Hosting Guide

### Step 1: Build the Vite Frontend for Production
Before uploading, build the static assets on your local machine:
1. Open your project terminal.
2. Run the production build command:
   ```bash
   cmd /c npm run build
   ```
3. This creates a highly optimized `dist/` directory at your root containing the `index.html`, CSS, JS, and image assets. This `dist/` folder is what will be served to public visitors.

---

### Step 2: Set Up MySQL on Spaceship
1. Log in to your **Spaceship Account** and navigate to your **cPanel Dashboard**.
2. Under the **Databases** section, click **MySQL® Databases** (or **MySQL® Database Wizard**).
3. **Create Database**: Name it `primebridge` (cPanel will prepend your username, e.g., `user_primebridge`). Click **Create**.
4. **Create Database User**: Scroll down to "MySQL Users". Create a user (e.g., `user_admin`), set a strong password, and click **Create User**.
5. **Add User to Database**: Under "Add User To Database", select your newly created user and database, then click **Add**.
6. **Assign Privileges**: Select **ALL PRIVILEGES** and click **Make Changes**.
7. *Note down the full database name, username, and password for your `.env` variables!*

---

### Step 3: Configure the Node.js Express App in cPanel
Spaceship's shared hosting manages Node.js processes using **Phusion Passenger**.
1. In cPanel, scroll to the **Software** section and select **Setup Node.js App**.
2. Click **Create Application** and fill out the details:
   - **Node.js Version**: Select the latest stable version (e.g. `20.x` or `22.x`).
   - **Application Mode**: Select `Production`.
   - **Application Root**: Enter a name for the server folder (e.g. `primebridge-backend`).
   - **Application URL**: Select your subdomain or URL path where the API will live (e.g., `api` or `domain.com/api`).
   - **Application Startup File**: Enter `server/index.cjs` (or `index.cjs` if you move it to the root of the app).
3. Click **Create**.
4. Once created, cPanel will display a command at the top starting with:
   `source /home/username/nodevenv/...`
   *Copy this command. It allows you to run terminal scripts in the Node virtual environment.*

---

### Step 4: Upload Backend Files & Environment Setup
1. In cPanel, go to **Files > File Manager**.
2. Navigate to the **Application Root** directory you created in Step 3 (e.g., `primebridge-backend`).
3. Upload your backend files:
   - `server/index.cjs`
   - `server/db.cjs`
   - `package.json`
4. **Configure Environment Variables**:
   - In the **Setup Node.js App** page in cPanel, edit your app and scroll to **Environment variables**.
   - Add your MySQL production variables dynamically (this is much more secure than placing raw `.env` files in your public folder):
     - `DB_HOST` = `localhost`
     - `DB_PORT` = `3306`
     - `DB_USER` = `user_admin` (your cPanel MySQL username)
     - `DB_PASSWORD` = `your_db_password`
     - `DB_NAME` = `user_primebridge` (your cPanel MySQL database name)
     
     > [!IMPORTANT]
     > **NEVER set a manual `PORT` variable in cPanel environment settings.** 
     > Spaceship hosting uses Phusion Passenger to serve your Node app. Passenger automatically overrides `process.env.PORT` with a dynamic Unix pipe socket to route public traffic. Overriding this to `5000` will crash your startup socket bind! Leave it out completely.
     
5. Click **Run NPM Install** in the cPanel Node setup dashboard. It will read your `package.json` and download Express, CORS, and MySQL modules automatically on the server.
   
   > [!WARNING]
   > **Is the "Run NPM Install" button disabled or failing?**
   > This is a very common cPanel sync behavior. Here are the 3 quick fixes:
   > 
   > 1. **Reload the cPanel Page**: If you uploaded `package.json` via File Manager in another tab, cPanel's Node App setup page doesn't know it's there yet. **Reload the entire browser page** in cPanel, click **Edit** on your app, and the button will light up!
   > 2. **Double Check the Directory**: Ensure `package.json` is uploaded directly inside the **Application Root** folder (e.g., `/home/username/primebridge-backend/package.json`), NOT inside `public_html` and NOT inside a `server` subfolder.
   > 3. **The 100% Terminal Bypass (Recommended)**: cPanel's web interface can sometimes time out on heavy installations. Bypass it completely using cPanel's built-in **Terminal** tool:
   >    - Open **Terminal** in cPanel (under the Advanced section).
   >    - Paste and run the environment command shown at the top of your Node setup page (it activates the Node virtual environment):
   >      ```bash
   >      source /home/username/nodevenv/primebridge-backend/20/bin/activate && cd /home/username/primebridge-backend
   >      ```
   >    - Run standard npm install directly:
   >      ```bash
   >      npm install
   >      ```
   >    - This bypasses all cPanel UI lag and shows you the installation progress in real-time!

6. Click **Restart** to boot the backend server process.

---

### Step 5: Upload the Vite Frontend (Using dist.zip)
We have fully automated the frontend deployment for you! The production build process now copies a pre-configured `.htaccess` file into your `dist/` directory, and packages everything into a convenient `dist.zip` file at the root of your project.

1. In cPanel **File Manager**, navigate to the **public_html** folder (or the root directory of your domain/subdomain).
2. Click **Upload** at the top, select the `dist.zip` file from your local computer's project root (e.g. `c:\Users\User\Desktop\Websites\PrimeBridgeHoldings\dist.zip`).
3. Once the upload is 100% complete, go back to the File Manager, click on `dist.zip`, and click **Extract** in the top cPanel menu.
4. Extract the contents directly into `public_html`.
5. You can now delete the `dist.zip` file from cPanel to save space.

---

### Step 6: Automated SPA Routing & API Configuration (.htaccess)
Since React Router manages routes client-side (e.g., `/holdings`, `/about`, `/admin`, `/admin/login`), refreshing the page on these paths would normally trigger a **404 Not Found** error under cPanel Apache.

To solve this, our pre-packaged `dist.zip` automatically extracts a pre-configured `.htaccess` file directly into your `public_html` directory with the following contents:

```apache
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  
  # Do not rewrite API requests (let Passenger handle /api)
  RewriteCond %{REQUEST_URI} ^/api [NC]
  RewriteRule .* - [L]
  
  # Direct all other routes to index.html
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>
```

> [!NOTE]
> If you already had an existing `.htaccess` file, extracting the zip will overwrite or merge it. Ensure the rules above exist at the top of your `.htaccess` so React Router doesn't conflict with any other server redirects!

## 💡 Advanced Production Tips & Troubleshooting

### 1. Handling Large Base64 Image Uploads
Since we are using the BlockNote editor and cover image uploads (which compile into base64 data URLs), the HTTP payloads can be quite large.
- In your Express app (`server/index.cjs`), we have already set up default body limits. If you encounter a `413 Payload Too Large` error, double-check that your Express server has body parser limits raised:
  ```javascript
  app.use(express.json({ limit: '50mb' }));
  app.use(express.urlencoded({ limit: '50mb', extended: true }));
  ```

### 2. Accessing node CLI on Spaceship via SSH
If you have SSH access to your Spaceship account:
1. Log in via your terminal: `ssh username@spaceship-server-ip`
2. Run the virtual environment command you copied in **Step 3**:
   ```bash
   source /home/username/nodevenv/primebridge-backend/20/bin/activate && cd /home/username/primebridge-backend
   ```
3. Now you can run `npm install` or execute seed scripts directly from the terminal!

### 3. Restarting the Server
Shared hosting processes can be cached. Whenever you edit your backend files (`index.cjs` or `db.cjs`), you **must** click **Restart** inside the cPanel **Setup Node.js App** page to apply the changes.
